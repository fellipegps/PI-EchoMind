    ADR-005 — Supabase Auth e escopo administrativo¶

    Status · observada no repositório
    Revisão analisada · f05f1f8

    Contexto comprovado¶

    O painel precisa de uma sessão de usuário para chamar as operações administrativas da API. O portal público resolve a instituição pelo slug da configuração. (echomind-front/lib/api.ts:264-289, echomind-backend/app/main.py:399-430)

    Decisão observada¶

    O navegador usa o SDK do Supabase para login, cadastro e recuperação. Depois do login, envia o access token como Bearer à API. A dependência do FastAPI chama supabase.auth.get_user com o token e deriva a identidade administrativa do ID retornado. (echomind-front/lib/supabase.ts:1-6, echomind-front/lib/api.ts:264-289, echomind-front/lib/api.ts:333-393, echomind-backend/app/auth.py:26-61)

    Consequências demonstráveis¶

    A API usa o ID autenticado para inicializar a configuração do tenant e limitar o acesso aos recursos. O fluxo de validação depende da resposta do Supabase Auth. Token inválido ou ausência do usuário com e-mail gera 401 no validador, e as rotas legadas verificam divergência de tenant com 403. Os metadados de perfil alimentam nome e instituição, enquanto a autorização usa o ID verificado. (echomind-backend/app/auth.py:26-61, echomind-backend/app/main.py:191-214, echomind-backend/app/main.py:247-254, echomind-backend/app/main.py:377-409)

    Dúvidas¶

    F03-01 acompanha a localização das motivações históricas da adoção do Supabase Auth. As configurações do serviço e do banco hospedados são observações separadas do fluxo implementado.

    Evidências¶

    Figura 1 — echomind-backend/app/auth.py:26-56, revisão f05f1f8.

    O que prova. O validador consulta o Supabase com o token recebido e usa a identidade da resposta. O uso desse ID para escopo está em echomind-backend/app/main.py:191-214.

    Fontes

    • echomind-front/lib/supabase.ts:1-6 e echomind-front/lib/api.ts:333-393 — sessão no cliente.
    • echomind-front/lib/api.ts:264-289 e echomind-backend/app/auth.py:26-61 — transporte e validação do Bearer.
    • echomind-backend/app/main.py:191-214, echomind-backend/app/main.py:247-254 e echomind-backend/app/main.py:399-409 — onboarding, perfil e checagem de escopo.
