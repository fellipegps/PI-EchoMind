    Instalação local¶

    Prepare backend e frontend em terminais separados. Para uma demonstração de interface sem provedores, use as fixtures do roteiro manual; o fluxo completo de autenticação e RAG exige serviços de desenvolvimento configurados.

    Ferramentas e cópia de trabalho¶

    Use Python 3.12, Node 22 e pnpm 10.30.0, conforme a CI. O README aceita Node 20+, mas a reprodução dos jobs usa 22. Docker com motor Linux é necessário para os ensaios de banco e deploy (README.md:62-75; .github/workflows/ci.yml:18-36, .github/workflows/ci.yml:48-58, .github/workflows/ci.yml:156-180).

    Antes de testar uma revisão, confira a branch, o commit e as alterações nas fontes. Para evitar configurações privadas, extraia uma cópia com git archive:

    git status --short --branch
git rev-parse HEAD
git diff --name-only -- echomind-backend echomind-front deploy .github
$copiaCi = Join-Path ([IO.Path]::GetTempPath()) ('echomind-ci-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $copiaCi
$arquivoFonte = Join-Path $copiaCi 'fonte.tar'
git archive --format=tar --output=$arquivoFonte HEAD
tar -xf $arquivoFonte -C $copiaCi
Set-Location $copiaCi

    O diretório temporário externo também evita a ausência de classes de utilidade observada na prévia sob uma pasta ignorada. Remova a cópia apenas depois de guardar o resumo revisado. A verificação desta fase usou essa estratégia, sem diferenças locais nas fontes de aplicação.

    Backend¶

    A partir da raiz da cópia:

    cd echomind-backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
python -m pip install -r requirements.txt -r requirements-dev.txt
Copy-Item .env.example .env

    Em Bash, substitua a criação/ativação por python3.12 -m venv .venv e source .venv/bin/activate. O procedimento está em README.md:110-149; os requisitos de teste estão em echomind-backend/requirements-dev.txt:1-5.

    Preencha o arquivo local com os valores do projeto de desenvolvimento, sem imprimi-lo no terminal. O catálogo de ambiente (registro interno) explica as demais opções.

    Variável Configuração mínima e destino
    DATABASE_URL Conexão privada do banco de desenvolvimento, valor ****
    SUPABASE_URL e SUPABASE_SECRET_KEY Projeto de Auth de desenvolvimento; chave secreta somente no backend, ****
    GROQ_API_KEY Credencial do provedor para o chat real, ****
    ALLOWED_ORIGINS Origens locais exatas, como http://localhost:3000 e http://127.0.0.1:3000
    EMBED_MODEL e EMBEDDING_DIM Exemplo versionado: E5 small e 384 dimensões
    DOCUMENT_STORAGE_DIR Diretório local de originais; precisa permanecer gravável

    As fontes são echomind-backend/.env.example:1-56. A suíte rápida utiliza SQLite e mocks próprios; não precisa das credenciais reais dessa tabela.

    F04-01 — instalação conferida

    email-validator==2.3.0 está nos requisitos do backend. Em venv nova de Python 3.12.10, instalar os dois requisitos declarados e coletar a suíte passou sem instalar dependências manualmente.

    Confirme o banco escolhido antes de aplicar o schema. Para testar migrations, prefira o banco descartável.

    python -m alembic upgrade head
python -m uvicorn app.main:app --reload

    A API de desenvolvimento usa http://localhost:8000 (README.md:204-219). A saúde em /health mede liveness; não valida Auth, geração ou embeddings (echomind-backend/Dockerfile:37-43).

    Frontend¶

    Em outro terminal, na raiz da cópia:

    cd echomind-front
corepack pnpm --version
corepack pnpm install --frozen-lockfile
Copy-Item .env.local.example .env.local

    Confira 10.30.0 e preencha as três variáveis públicas:

    Variável Valor de desenvolvimento
    NEXT_PUBLIC_API_URL http://localhost:8000 para a API local
    NEXT_PUBLIC_SUPABASE_URL URL do mesmo projeto Auth configurado no backend, ****
    NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY Chave publicável desse projeto, ****

    A configuração do mapa acrescenta URL e atribuição do provedor; imagens aéreas são opcionais (echomind-front/.env.local.example:1-11). Chaves secretas, conexão do banco e credencial Groq permanecem no backend (README.md:242-260).

    corepack pnpm dev

    Abra http://localhost:3000/login e reinicie o Next.js após alterar variáveis (README.md:262-290). Para encerrar, use Ctrl+C nos dois terminais e deactivate na venv.

    Alternativa em contêiner¶

    O Dockerfile fixa Python 3.12 por digest, instala requirements-deploy.lock com hashes e executa com UID 10001. Ele copia explicitamente código e migrations, sem carregar os arquivos locais de configuração. Não roda migrations automaticamente. Siga o roteiro de deploy (registro interno) para a operação em contêiner (echomind-backend/Dockerfile:1-44).
